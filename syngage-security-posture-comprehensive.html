Platform Coverage Analysis (8 Tier 1–2 Gaps)

Focused view of critical 8 Tier 1–2 gaps only. Which can be offloaded to platform capabilities (Modal, Render, Supabase) vs. requiring custom application code? → See Master Table (filter: Tier 1–2, Status: Gap) for complete view.

Reality check: Modal and Render are compute/hosting platforms, not security-focused. They provide basic DDoS protection and TLS, but most security controls must be built in the application layer.

App-layer rate limiting / WAF / bot protection
Tier 1 — Deal-blocker
Custom + Modal
Platform: Render has edge-level DDoS mitigation; Modal has function concurrency limits (not per-client rate limiting).
Gap: No per-endpoint, per-user rate limiting on FastAPI or Next.js routes.
Solution: Use Upstash Redis + SlowAPI middleware on Modal + Next.js middleware on Render. Effort: M
Multi-factor authentication (MFA/TOTP)
Tier 1 — Deal-blocker
Supabase config
Platform: Supabase Auth has TOTP fully supported, currently disabled in config.toml.
Gap: Need Syngage_UI UI to enroll/manage TOTP (generate QR, recovery codes, verify on login).
Solution: Enable in config, wire enrollment flow in UI. Effort: S–M

Tier 1 — Deal-blocker
Supabase config
Platform: Supabase Auth has SAML/OIDC support, currently disabled in config.toml.

Solution: Enable in config, wire IdP choice on login page. Effort: M

SOC 2 Readiness: Common Criteria Audit

Syngage's compliance status against Security (mandatory) and Confidentiality criteria. Maps current controls to 9 Common Criteria (CC1–CC9) SOC 2 tests. Also visible in Master Table (filter by Type: SOC 2).

Mandatory criterion is Security (CC1–CC9). Because Syngage stores customer positioning and prospect PII, Confidentiality is recommended as the second criterion. Start with a Type 1 report (point-in-time), then Type 2 (3–12 month observation window).

Common Criteria Readiness

Path to SOC 2 Report

The shortcut: Most of your CC6/CC7 evidence is engineering work you're already prioritizing (Tier 1–2 gaps). Shipping MFA, SSO, rate limiting, audit log, RBAC, idle timeout directly produces the controls SOC 2 tests. The genuinely new effort is CC1–CC5 — policies, risk assessment, monitoring — which is documentation and process, best run in parallel using a compliance-automation tool (e.g., Vanta, Drata).

Company Fit: Which Controls to Prioritize

Not every control is worth a small team's time right now. This view sorts gaps by what a lean company can realistically own — so you invest where it counts and don't over-engineer.

Rule of thumb: Ship everything in the green lane now (config toggles, managed services, modest builds). Spin up amber items when a specific deal or SOC 2 requires them. Treat the red lane as sales-driven — build only when a signed enterprise contract pays for it.
