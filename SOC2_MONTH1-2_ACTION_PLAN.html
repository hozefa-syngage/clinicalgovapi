4. DATA CLASSIFICATION LEVELS

All data falls into one of four categories:

4.1 PUBLIC DATA

Definition: Data safe for public consumption without restriction

Examples: Marketing blog posts, published case studies, press releases

Handling: No special access controls, no encryption required, can be shared publicly

4.2 INTERNAL DATA

Definition: Non-sensitive business information for internal use only

Examples: Meeting notes, org charts, internal announcements, project plans

Access: Employees only, no external sharing without approval

Retention: 3 years minimum, then delete securely

4.3 CONFIDENTIAL DATA

Definition: Business-sensitive information with risk if disclosed

Examples: Customer data, financial info, IP, pricing, vendor contracts

Access: Need-to-know basis only, documented access log maintained

Handling Requirements:

  • Encrypted at rest (all systems must use encryption)
  • Encrypted in transit (HTTPS/TLS 1.2 minimum)
  • No storage on personal devices (see BYOD policy)
  • No forwarding to personal email accounts

Retention: Per customer contract (typically 7 years for audit), then securely delete

4.4 RESTRICTED DATA

Definition: Highly sensitive credentials and authentication materials

Examples: API keys, database passwords, AWS credentials, SSH private keys

Handling: Stored ONLY in encrypted vault (1Password, Bitwarden). Never in code, email, or Slack.

Rotation: Rotate every 90 days. Delete immediately when no longer needed.

5. DATA HANDLING RULES

  • ✓ All data encrypted at rest (databases, file storage)
  • ✓ All data encrypted in transit (TLS 1.2+ minimum)
  • ✓ Access logged (who accessed what, when)
  • ✓ Data backups created daily (retention: 30 days minimum)
  • ✗ NO customer data on personal devices (BYOD policy)
  • ✗ NO screenshots of sensitive data without redaction
▼ PAGE 3: Incident Response & Breach Notification

6. DEFINITION OF A SECURITY INCIDENT

Any of the following constitutes a security incident:

  • Unauthorized access to company systems or customer data
  • Data breach (customer information exposed)
  • Malware or ransomware infection
  • Compromised credentials or credentials accessed
  • DDoS or other cyber attack
  • Phishing emails with successful compromise
  • Accidental disclosure of confidential information

7. INCIDENT RESPONSE PROCEDURE

All incidents follow this 5-step process:

STEP 1: DISCOVER & REPORT (Within 15 minutes)

Action: Any employee who discovers an incident must report immediately to security@syngage.ai

DO NOT: Delete evidence, restart systems, or post about it on Slack before CISO is notified

STEP 2: TRIAGE & INITIAL RESPONSE (Within 1 hour)

  • CRITICAL: Customer data exposed, system down → Notify CEO + Board within 1 hour
  • HIGH: Suspected breach, unauthorized access → Notify VP Eng + CEO within 2 hours
  • MEDIUM: Suspicious activity, potential vulnerability → Notify VP Eng within 4 hours
  • LOW: Minor security event, false alarm → Log in incident tracker

STEP 3: INVESTIGATION (Within 5 business days)

  • Collect system logs (7+ days)
  • Database access logs
  • Timeline documentation (hour-by-hour)
  • Root cause analysis

STEP 4: REMEDIATION & NOTIFICATION (Within 72 hours)

  • If no breach: Fix vulnerability + notify CEO
  • If breach confirmed: Notify customers within 24-72 hours (GDPR/CCPA requirement)
  • Offer free credit monitoring if PII affected

STEP 5: POST-INCIDENT REVIEW (Within 10 business days)

Blameless postmortem: What happened? Why was it possible? How do we prevent it?

8. BREACH NOTIFICATION TIMELINES

  • GDPR (EU): Notify within 72 hours of discovery
  • CCPA (California): Notify within 30 days
  • Syngage Standard: Critical (24 hours), High (72 hours)
▼ PAGE 4: Asset Management & BYOD Policy

9. COMPANY ASSET MANAGEMENT

All company-owned devices are company property and subject to monitoring.

9.1 LAPTOPS & DESKTOPS

Security Controls:

  • ✓ Full-disk encryption mandatory (BitLocker on Windows, FileVault on Mac)
  • ✓ Antivirus/EDR software installed
  • ✓ Auto-lock after 5 minutes of inactivity
  • ✓ Password required (see password policy)
  • ✓ Windows/macOS updates installed automatically
  • ✓ Firewall enabled

Lost or Stolen Device:

  • Report to IT immediately
  • CISO disables remote access
  • For encrypted device: Assume data secure (encryption prevents access)
  • For non-encrypted device: Report as potential breach

9.2 MOBILE DEVICES

Policy:

  • ✓ Company-issued devices enrolled in Mobile Device Management (MDM)
  • ✓ MFA required for any company app access
  • ✓ Auto-lock after 5 minutes inactivity
  • ✗ NO customer data access
  • ✗ NO production logs/dashboards
  • ✗ NO API credentials

Termination: IT performs remote MDM wipe (all data deleted) on day of separation

9.3 BYOD (BRING YOUR OWN DEVICE) POLICY

STRICTLY PROHIBITED:

  • ✗ Accessing customer data on personal laptop
  • ✗ Viewing production logs on personal tablet
  • ✗ Checking API credentials on personal phone
  • ✗ Screenshots of customer information

ALLOWED ON PERSONAL DEVICES:

  • ✓ Email (Slack, Gmail) - read-only
  • ✓ Calendar/scheduling
  • ✓ Public documentation

Consequences: First violation: Warning + retraining. Repeat: Written warning. Third: Potential termination.

9.4 DEVICE DECOMMISSIONING

Laptops: Full-disk wipe before disposal using built-in OS tools or physical drive destruction

Mobile (Company-Issued): IT performs remote MDM wipe. Collect device for recycling.

Criteria for Physical Destruction: Devices with unencrypted storage, drives showing tampering, or highly sensitive data processing

▼ PAGE 5: Password & Authentication Policy

10. PASSWORD POLICY

All passwords protecting company systems and customer data must comply with these standards:

10.1 PASSWORD COMPLEXITY

Minimum Requirements:

  • ✓ Minimum 12 characters (longer is better: 16+ recommended)
  • ✓ At least 1 UPPERCASE letter (A-Z)
  • ✓ At least 1 lowercase letter (a-z)
  • ✓ At least 1 number (0-9)
  • ✓ At least 1 special character (!@#$%^&*)

What NOT to use:

  • ✗ Dictionary words (password, welcome, admin)
  • ✗ Company name or employee name
  • ✗ Repeating characters (11111, aaaaa)
  • ✗ Personal information (birthdate, phone number)
  • ✗ Previously used passwords

10.2 PASSWORD MANAGEMENT

Storage: Store in encrypted password manager (1Password, Bitwarden, LastPass)

NOT in: Browsers, paper, email, Slack, or code repositories

Change Frequency:

  • Initial password (first login): MUST change immediately
  • Scheduled expiry: Every 90 days
  • Emergency: Change immediately if suspected compromise
  • History: Cannot reuse last 5 passwords

10.3 MULTI-FACTOR AUTHENTICATION (MFA)

MFA is MANDATORY for:

  • ✓ Company email/SSO login
  • ✓ All admin or production system access
  • ✓ All cloud platforms (Supabase, AWS, Modal, Render)
  • ✓ GitHub (especially main branch)
  • ✓ VPN access

Acceptable MFA Methods (Ranked):

🥇 TIER 1 - MOST SECURE: Hardware security key (Yubikey, Google Titan)

🥈 TIER 2 - RECOMMENDED: Time-based OTP app (Google Authenticator, Authy, 1Password)

🥉 TIER 3 - ACCEPTABLE: Push notification approval (Microsoft Authenticator)

❌ NOT ACCEPTABLE: SMS (vulnerable to SIM-swap), Email-based codes

Backup Codes: Save 10-12 one-time codes in 1Password vault or printed in safe

MFA Device Loss: Report to IT immediately, disable MFA using backup codes, change password, re-enable with new device

10.4 ENFORCEMENT & MONITORING

Audited: Quarterly by CISO

Violations: First violation: Warning + retraining. Repeated: Performance review. Intentional circumvention: Termination.

SYNGAGE AI ANNUAL INFORMATION SECURITY RISK ASSESSMENT

Assessment Date: [TODAY]
Assessment Period: [YEAR]

1. EXECUTIVE SUMMARY

This assessment identifies and prioritizes information security risks facing Syngage AI, including technical, operational, and compliance risks. It serves as the foundation for our SOC 2 roadmap and security budget allocation.

2. METHODOLOGY

We used a NIST Cybersecurity Framework approach:

RISK SCORING: Likelihood × Impact

  • Likelihood: 1 (Very Low) → 5 (Very High)
  • Impact: 1 (Negligible) → 5 (Catastrophic)
  • Risk Score: Likelihood × Impact = 1-25

RISK RATING:

  • Critical (20-25): Immediate action required
  • High (12-19): Address within 90 days
  • Medium (6-11): Address within 6 months
  • Low (1-5): Accept or monitor

3. RISK ASSESSMENT SCOPE

In Scope:

  • ✓ Syngage Platform (cloud infrastructure, API, database)
  • ✓ Customer Data (PII, clinical trial data)
  • ✓ Employee Access & Systems (laptops, email, development)
  • ✓ Third-party Integrations (APIs, vendors)
  • ✓ Compliance (SOC 2, GDPR, CCPA)

  • Likelihood: 3 | Impact: 4 | Score: 12 (HIGH)
